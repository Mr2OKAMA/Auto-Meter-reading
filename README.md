# Auto-Meter-reading

スマートフォンのブラウザから入力できる、日常点検用の軽量Webフォームです。

## サイト

- [日常点検フォームを開く](https://mr2okama.github.io/Auto-Meter-reading/daily_inspection_form.html)
- [リポジトリ](https://github.com/Mr2OKAMA/Auto-Meter-reading)

> GitHub Pagesで公開する場合は、リポジトリの **Settings → Pages** で公開設定を行ってください。公開後のサイトURLは通常、`https://mr2okama.github.io/Auto-Meter-reading/daily_inspection_form.html` です。

## 使い方

### 1. フォームを開く

`daily_inspection_form.html` をスマートフォンのブラウザで開きます。

### 2. 前回データを読み込む

画面上部の **「JSONファイルを選択またはドラッグ&ドロップ」** をタップし、前回保存した `inspection_summary_*.json` を選択します。

読み込みに成功すると、各施設・各項目の下に前回値が表示されます。

### 3. 点検日と点検時間を確認する

- **点検日**：現在の日付が自動入力されます。必要に応じて変更してください。
- **点検時間**：流量計施設は各施設ごとに入力します。入力欄をタップすると **「現在時間を入力」** ボタンが表示されます。

### 4. メーター値を入力する

以下の設備群に対応しています。

- **流量計施設**
  - 緑苑：電力量、流量（×10m3）
  - 深田酒倉：電力量、流量（深田）（×10m3）、流量（酒倉）（×10m3）
  - 川辺、八百津、和知、中恵土、川島第二、米野、東部第二、下羽栗、梅松、東部第一、芥見：点検時間、電力量、流量
  - 川島第二の二（環境楽園）、岐南西：点検時間、流量
- **上水・燃料・放流口**
  - 兼山ポンプ場：上水メーター、小出槽 油量
  - 川島ポンプ場：上水メーター
  - 長森ポンプ場：上水メーター、地下燃料 移送カウンター値合計、小出槽、井水メーター
  - 岐南ポンプ場：上水メーター（親）、上水メーター（子）、地下燃料 移送カウンター値、小出槽、井水メーター
  - Ａ点（三井川放流口）、Ｂ点（中屋川放流口）、Ｃ点（中部排水放流口）、Ｄ点（中屋川排水放流口）、Ｅ点（徳田支線放流口）：電力量

前回値を確認しながら、今回の値を入力できます。流量計施設の必須項目に加えて、上水・燃料・放流口の追加項目は必要なものだけ入力できます。

### 5. JSONファイルとして保存する

**「JSONファイルとして保存」** ボタンをタップすると、入力した全施設のデータが1つのJSONファイルとしてダウンロードされます。

ファイル名は次の形式です。

```text
inspection_summary_YYYYMMDD.json
```

例：

```text
inspection_summary_20260925.json
```

次回の点検時にこのJSONファイルを読み込むことで、前回値と今回値を比較できます。

## JSON形式

保存されるJSONデータは次の形式です。

```json
{
  "点検日": "2026-09-25",
  "データ一覧": [
    {
      "施設キー": "ryokuen",
      "施設名": "緑苑",
      "区分": "流量計施設",
      "点検時間": "09:00",
      "測定値": {
        "電力量": 340.5,
        "流量": 1250.0
      }
    },
    {
      "施設キー": "ginan_pump",
      "施設名": "岐南ポンプ場",
      "区分": "上水・燃料・放流口",
      "測定値": {
        "上水メーター（親）": 120.0,
        "上水メーター（子）": 118.5,
        "地下燃料 移送カウンター値": 42.0,
        "小出槽": 250.0,
        "井水メーター": 88.0
      }
    }
  ]
}
```

### 旧JSONとの互換性

- 新しい保存形式では、各施設を **施設キー + 測定値オブジェクト** で保存します。
- 読み込み時は、まず `施設キー` が一致するデータを使い、一致しない場合だけ `施設名` が現在の施設一覧と一致するデータを使って前回値を表示します。
- 現在の施設一覧に一致しない旧データ（例：`処理場A / 処理場B / 処理場C`）は自動的にスキップされます。
- `電力` という旧項目名の読み替えは、**現在の施設名または施設キーと一致するデータ** に対してだけ `電力量` として行われます。
- ローカルの一時保存データは、旧保存キーが見つかった場合に新しい保存キーへ移行されます。

## 注意事項

- 入力値やJSONファイルはブラウザ内で処理されます。
- 保存したJSONファイルは、次回の点検まで安全な場所に保管してください。
- GitHub Pagesで利用する場合は、Pagesの公開設定が必要です。
- Tailwind CSSをCDNから読み込むため、初回表示時などにインターネット接続が必要です。

## 検針記録.xlsm へのJSON自動記入（VBA）

`検針記録.xlsm` への自動記入用として、標準モジュール `InspectionJsonImporter.bas` を追加しています。

> このリポジトリ上の `検針記録.xlsm` は暗号化されており安全に直接編集できないため、`.bas` を同梱しています。

### 文字化け対策（.bas の保存形式）

- `InspectionJsonImporter.bas` は **UTF-8（BOM付き）** で管理しています。
- VBA のインポート時に日本語が化ける主因は、`.bas` が UTF-8（BOMなし）や文字コード不明な状態で保存されることです。
- このファイルを編集する場合は、**UTF-8（BOM付き）を維持**して保存してください。
- JSON読み込み処理（`ADODB.Stream` の `Charset = "utf-8"`）はそのままで、JSON内日本語の取り込み仕様は変更していません。

### 導入手順

1. `検針記録.xlsm` を開く（必要に応じて編集を有効化）
2. `Alt + F11` でVBEを開く
3. 対象ブックを選択し、`ファイル -> ファイルのインポート` で  
   `InspectionJsonImporter.bas`（リポジトリ直下）を取り込む
4. `Json点検データ取込_記録シート` マクロを実行する
5. JSONファイル選択ダイアログで `inspection_summary_*.json` を選ぶ
6. 点検日一致列・書込件数の確認ダイアログで内容を確認して実行する

### ラベル認識ルール（Sheet「記録」）

- 対象シートは `記録` 固定
- 日付列は **4行目** を走査し、各セルを日付として解釈してJSONの `点検日` と一致する列を選択
- 行探索は固定行番号ではなく、行ラベル文字列（先頭12列）から次を判定
  - 施設: `施設キー` 優先、不一致時は `施設名` でフォールバック
  - 項目: `電力 -> 電力量` などの別名吸収後、項目名ラベルに一致した行へ記入
- `点検時間` は、施設文脈と「点検時間」ラベルがシート上で特定できた場合のみ記入  
  （不明確な場合はスキップし、測定値記入を優先）
- `点検時間` 値は `HH:MM` / `H:MM` / `HH:MM:SS` 形式として解釈できる場合のみ記入し、解釈不能値はスキップ

### JSON項目からExcelセルへのマッピング方針

- `データ一覧[*].測定値` の各キーを対象行へ書き込み
- 桁落ちを避けるため、高精度の数値トークン（大きな整数・高精度小数）は文字列として保持したまま記入
- 代表的な別名吸収:
  - `電力` → `電力量`
  - `流量(深田)` → `流量（深田）`
  - `流量(酒倉)` → `流量（酒倉）`
  - `上水メーター(親)` / `上水メーター(子)` → 全角括弧表記へ正規化

### 空値・null・欠落項目の扱い

- 空文字 / `null` / 欠落は **書き込みスキップ**（既存セル値を保持）
- 廃止項目（例: 岐南ポンプ場の `上水メーター（子）`・`小出槽`、長森ポンプ場の `小出槽`）が空/nullでも、**0で上書きしない**
- 未知の施設・未知の測定項目はスキップし、件数を結果メッセージで通知

### 検証手順（手動）

1. VBAエディタで `デバッグ -> VBAProjectのコンパイル` を実行
2. 以下を満たすJSONで `Json点検データ取込_記録シート` を実行
   - `点検日` が4行目に存在する日付
   - 既知施設・既知項目・未知項目を混在
   - 空文字/nullを含む（廃止項目含む）
3. 確認ポイント
   - 日付一致列にのみ書き込まれる
   - 未知項目はスキップされる
   - 空文字/nullで既存値が0に変わらない
   - `点検時間` は対応欄が特定できた場合のみ反映される
4. 追加の自動チェックとして `Json点検データ取込_セルフテスト` を実行し、  
   日付正規化・別名吸収・不正JSON拒否（末尾ゴミ/不正数値）を確認する
